Изучить HTTP-маршруты, формы, шаблоны, JSON API, подключение базы данных
и двусторонний обмен через WebSocket. Используются FastAPI, Jinja2 и SQLite.
Источник: методичка «Методы и технологии программирования», часть 1,
лабораторная №6, страницы 11–12. Строка варианта 2: средние 2, 4, 7;

| Задание | Реализация | Проверка |

| Среднее №2: форма, имя → приветствие | GET `/`, POST `/greet`, шаблон home.html | Ввести имя, получить «Привет, Илья!» |
| Среднее №4: страница с таблицей | GET `/messages`, messages.html, строки из SQLite | Отправить сообщение, открыть таблицу |

| Повышенное №2: FastAPI с базой данных | `Database`, insert/get/list, таблица messages | POST и GET API, сохранение после перезапуска |

Все пять заданий объединены в одно приложение. Flask не требуется:
задания варианта используют FastAPI. Обязательного развёртывания на хостинге
в варианте 2 нет.

## Установка и запуск

Проверено на Python 3.12.14. Для CI выбраны Python 3.12, 3.13 и 3.14.
Из корня репозитория на Windows:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Откройте **http://127.0.0.1:8766/**. Для остановки сервера нажмите Ctrl+C
в терминале. Порт 8766 выбран, потому что на исходном компьютере порт 8000
недоступен. Альтернативный запуск с другим свободным портом:

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8767
```

На Linux/macOS используйте `.venv/bin/python` вместо пути к Scripts.
Активировать виртуальное окружение необязательно. Зависимости и их версии
зафиксированы в requirements.txt. После установки библиотек основные страницы
и чат не требуют интернета; Swagger UI может загружать свои ресурсы из CDN.

## Демонстрация всех заданий

1. Открыть главную страницу, ввести имя и нажать «Поздороваться».
2. Открыть `/api/info`: вернутся номер лабы, вариант, ФИО и группа в JSON.
3. Открыть `/chat` в двух вкладках. В одной указать «Илья», в другой «Олег».
   Дождаться статуса «В сети», отправить сообщение и ответ. Оба сообщения
   появятся в обеих вкладках без обновления страницы.
4. Открыть `/messages`: видны ID, автор, текст и время UTC в таблице.
5. Остановить и запустить сервер снова. Таблица и история чата сохранятся.
6. В чате после остановки соединения нажать «Переподключить» после запуска
   сервера: история загрузится заново без дубликатов.
7. Через `/docs` выполнить POST `/api/messages`, затем GET `/api/messages`.
   Сообщение, созданное через HTTP, также рассылается открытым участникам чата.

Пример тела POST `/api/messages`:

```json
{"name": "Илья", "text": "Проверка лабораторной №6"}
```

Ответ имеет статус 201 и поля `id`, `name`, `text`, `created_at`.
GET `/api/messages/{id}` возвращает запись или 404, если её нет.
Параметр `limit` у списка принимает значения 1–100, по умолчанию 100.

## Объяснение реализации

**HTTP и шаблоны.** GET получает страницу или данные, POST передаёт форму
или JSON. Jinja2 вставляет значения в HTML с автоматическим экранированием.
Имя в форме очищается от пробелов по краям, длина ограничена 40 символами.
Неверный ввод возвращает статус 422 и понятное сообщение.

**База.** SQLite хранит ID, автора, текст и время создания. Соединение
открывается для каждой операции и гарантированно закрывается; запись
выполняется в транзакции. Значения подставляются через `?`, а не склейку SQL.
История выбирается по последним ID, затем возвращается в порядке отправки.
Операции SQLite в асинхронных обработчиках вынесены через `asyncio.to_thread`.

**WebSocket.** После подключения клиент получает `history` с последними
100 сообщениями. Клиент отправляет JSON `{name, text}`. Сервер проверяет
его схемой Pydantic, сохраняет в базу и рассылает событие `message`
всем подключённым участникам, включая отправителя. Ошибки формата
возвращаются событием `error`, после которого можно отправить корректный ввод.
Регистрация нового клиента и отправка истории синхронизированы с записью
и рассылкой: сообщение не теряется между этими действиями.

Пустые строки, имя длиннее 40 и текст длиннее 1000 символов отклоняются.
Чат вставляет пользовательские данные через `textContent`, без `innerHTML`.
При отключении участник удаляется из набора соединений. Для отправки одному
клиенту установлен таймаут. Браузер показывает состояние подключения и
предоставляет кнопку переподключения; по ID исключаются дубликаты.

**Границы учебного проекта.** Это локальная общая комната без авторизации:
имя вводится самим участником. Для рассылки нужен один процесс Uvicorn
(не использовать несколько workers). Список соединений хранится в памяти,
сообщения — на диске. Редактирование и удаление сообщений не входят в
задание «FastAPI с базой данных»; реализованы сохранение и чтение.
Приложение предназначено для локальной демонстрации, не для публичного
многопользовательского сервиса. Успешный `send` в браузере не заменяет
подтверждение: сохранённое сообщение появляется после ответа сервера.


валидация, HTML-экранирование, SQL-строки как обычный текст, сохранение базы
при создании нового приложения, порядок истории, обмен двух WebSocket-клиентов,
переподключение и рассылка сообщений из HTTP API.

оно не является ошибкой, все проверки завершились успешно.
